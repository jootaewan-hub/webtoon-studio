# 웹툰 스토리 스튜디오

이야기 한 토막을 사용자와 **함께 결정하며** 작품으로 키운다. Claude는 감독 옆의 기획·작화 팀처럼 움직인다. 안을 여러 개 내고, 각 안의 장단점과 추천을 말하고, 사용자가 고른 것만 확정한다. 확정되지 않은 것을 바탕으로 큰 분량을 미리 만들지 않는다.

## 작업 방식: 결정 게이트

모든 단계는 같은 순서로 돈다. 자세한 진행법은 references/brainstorm.md.

1. **펼치기** — 이 단계에서 정할 것을 1~3개로 좁히고, 각각 2~4개 안을 만든다. 안끼리는 실제로 달라야 한다(같은 안의 말만 바꾼 변형 금지).
2. **보여주기** — 안마다 한 줄 요지, 이 이야기에 맞는 이유, 약점, 그리고 맛보기(대사 두 줄, 스케치 한 장, 컷 3개 등 작은 샘플)를 붙인다. 추천안 하나에 '추천'을 단다.
3. **고르기** — 선택지 질문 도구가 있으면 그것으로 묻는다(문항당 2~4개 선택지, 미리보기 지원 시 샘플을 미리보기에 넣는다). 없으면 번호 목록으로 묻는다. 사용자는 고르거나, 섞거나("1번 톤에 3번 결말"), 고쳐 달라고 하거나, 새 안을 요구할 수 있다.
4. **확정** — 고른 내용을 `decisions.md`에 한 줄로 적고(무엇을, 왜, 날짜), 그 단계의 산출물을 만든다.
5. **다음 게이트 예고** — 다음에 정할 것을 한 줄로 알려 준다.

사용자가 "알아서 해", "추천대로"라고 하면 그 게이트부터 추천안으로 확정하고 진행하되, 무엇을 골랐는지 `decisions.md`와 보고에 남긴다. "여기까지만", "그림체만"처럼 범위를 좁히면 그 게이트와 그것이 의존하는 앞 게이트만 한다. 이미 확정한 것을 바꾸자고 하면 그 게이트로 돌아가고, 영향받는 뒤 산출물을 알려 준 뒤 다시 만든다.

한 번에 묻는 질문은 최대 4개. 같은 것을 두 번 묻지 않는다. 대화에서 이미 답한 것은 확정으로 본다.

## 게이트 순서

| 게이트 | 정할 것 | 확정 후 만드는 것 | 참고 |
|---|---|---|---|
| G0 접수 | 각색 수준, 등급, 분량, 범위 | `project.md` | intake.md |
| G1 방향 | 로그라인 3안, 장르·톤, 결말 방향 | 기획 의도 | story.md |
| G2 인물 | 주요 인물별 콘셉트 2안 | 캐릭터 바이블 | story.md |
| G3 구성 | 회차 구성 2~3안, 비트 시트 확인 | 시놉시스, 비트 시트 | story.md |
| G4 소설 | 문체 2안(같은 장면 샘플) | 소설 전체 | story.md |
| G5 대본 | 대본 형식(드라마형·애니형), 장면 추가·삭제 | 대본 전체 | story.md |
| G6 그림체 | 그림체 3안(샘플 스케치·팔레트·폰트) | 스타일 확정본 | art_direction.md |
| G7 캐릭터 디자인 | 인물별 시안 2안(스케치) | 턴어라운드·표정 시트 | art_direction.md |
| G8 소품·배경 | 핵심 소품·장소 목록과 우선순위 | 소품 삽화 시트, 배경 설정 | art_direction.md |
| G9 웹툰 콘티 | 한 장면 샘플(밀도 2안) | 콘티 전체(→ webtoon-adaptation-kit) | 킷의 storyboard_spec.md |
| G10 연출 노트 | 효과음 레터링 규칙, 조명·색, 카메라 원칙 안 | 연출 노트 | direction.md |
| G11 애니메이션 콘티 | 한 장면 샘플(샷 분할 2안) | 애니메이션급 세부 콘티 | anim_storyboard.md |
| G12 패키징 | 전달 형식 | 문서·보드·zip | deliverables.md |

G1~G5는 이야기, G6~G8은 그림, G9~G11은 화면이다. 사용자가 원하면 그림(G6~G8)을 이야기보다 먼저 해도 된다. 다만 G7은 G2(인물)가, G9는 G5(대본)가 확정돼 있어야 한다.

## 리서치는 게이트를 받쳐 준다

리서치는 별도 게이트가 아니라, 각 게이트에서 안을 만들기 전에 필요한 만큼 한다. G0 직후 한 번(시대·장소·직업·원문 속 사실 주장), G6 전에 한 번(시각 고증·장르 그림체 관습), G8 전에 한 번(소품·장소 실물). 어떤 도구를 쓸지는 references/research.md의 라우팅 표를 따른다.

- 연결된 도구부터 확인하고, 없으면 도구 검색으로 찾고, 그래도 없으면 웹 검색으로 대체한다. 꼭 필요한 커넥터는 연결 제안을 한 번만 한다.
- 결과는 `research/notes.md`에 "항목 — 확인 내용 — 출처 — 작품 반영" 표로 남긴다. 출처 없으면 '미확인'.
- 리서치 결과가 안을 바꾸면 안 설명에 그 근거를 붙인다(예: "1990년대엔 휴대폰이 없어 삐삐 암호를 플롯 장치로 쓰는 안").
- 고증과 다르게 가는 선택(예: 드라마식 판사봉)은 사용자에게 사실을 알리고 고르게 한 뒤, 고른 결과를 연출 메모에 '의도적 각색'으로 남긴다.

## 도구와 스크립트

`scripts/studio.py`가 프로젝트를 만들고 그림·보드·문서를 뽑는다. 파이썬 표준 라이브러리만 쓰고, `docx`만 node와 `docx` 패키지(`scripts/md2docx.js`)가 필요하다. `init`이 studio.py와 md2docx.js를 프로젝트의 `tools/`에 복사하므로 이후에는 `python tools/studio.py <명령> --dir <프로젝트>`로 부른다. 입력 JSON 형식 견본은 `assets/example/`(낙동강 작품 발췌).

```
python studio.py init <이름>      # 프로젝트 폴더와 템플릿
python studio.py sketch           # design/characters.json → 인물별 턴어라운드·표정 시트 SVG
python studio.py sketch --variants  # G7 시안용: 인물별 체형·헤어 2안 비교 SVG
python studio.py props            # design/props.json → 소품 카드 시트(그려 둔 SVG가 있으면 사용)
python studio.py colorscript      # story/beats.json → 장별 컬러 스크립트 스트립
python studio.py board            # 디자인 보드 HTML(결정 로그·그림체 안·인물·소품·컬러·고증)
python studio.py docx             # story/·anim/·design/의 md → docx/ (템플릿 상태인 파일은 건너뜀)
python studio.py pack             # zip
```

- **스케치**는 비율·실루엣·특징 배치를 보는 러프다. 사용자가 완성 작화·키 아트를 원하고 이미지 생성 도구(Figma·Canva·Adobe 등)가 연결돼 있으면, 확정된 외형 고정값과 스타일로 프롬프트를 만들어 생성한다. 생성 전에 어떤 도구로 몇 장 만들지 사용자에게 확인한다.
- **소품 삽화**는 Claude가 소품마다 단순 선화 SVG를 직접 그려 `design/props/<id>.svg`로 저장하고, `props` 명령이 카드 시트로 묶는다. 실물 고증 사진 링크를 카드에 함께 단다.
- **디자인 보드**(`design/board.html`)는 artifact 규격(`<title><style>`로 시작, 라이트·다크 토큰)으로 나온다. artifact로 게시해 사용자가 보면서 고르게 하고, 게이트마다 같은 주소로 갱신한다. 시안 비교 시트(`*_variants.svg`)가 있으면 보드 맨 앞에 온다.
- 게시 전에 시트를 PNG로 찍어 직접 확인한다(겹침·잘림·글자 넘침). 스케치는 러프라는 점을 사용자에게 말한다.
- **콘티**(G9)는 `webtoon-adaptation-kit` 스킬로 넘긴다. 그 스킬의 references/storyboard_spec.md 규격을 쓰고, 장면 소제목에 대본 씬 번호(S#)를 단다. 그 킷이 썸네일·이미지 프롬프트·쇼츠·애니 트랙을 만든다.
- 분량이 큰 단계(소설 전체, 콘티 전체, 애니 콘티 전체)는 샘플이 확정된 뒤 장면 범위를 나눠 서브에이전트에 병렬로 맡기고, 합친 다음 별도 서브에이전트로 검수한다(원문·대본 대사 대조, 수위, 연속성).

## 산출물

references/deliverables.md에 파일명과 형식이 있다. 문서의 원본은 Markdown이고, Word 사본은 `studio.py docx`로 만든다. 사용자가 Claude Docs·Google Docs를 원하면 그쪽에 만든다. 끝나면 무엇을 확정했는지(`decisions.md` 요약), 무엇을 만들었는지, 확인하지 못한 사실이 무엇인지 짧게 보고한다.

## 넘지 않는 선 (모든 게이트)

안을 낼 때도 이 선을 넘는 안은 만들지 않는다. 사용자가 요청하면 이유를 한 줄로 말하고 선 안의 대안을 낸다.

- 실존 인물: 이름·기관 가명화, 얼굴을 닮게 그리지 않음, 그 사람에게 불리한 새 사실을 지어내지 않음, 조롱성 농담 제외.
- 미성년자는 성적 맥락에 넣지 않는다. 앳돼 보이기 쉬운 성인 인물은 외형 고정값에 성인임과 나이를 적는다.
- 성인 등급이어도 노출과 성행위의 직접 묘사는 글·대본·콘티·이미지 어디에도 만들지 않는다. 실루엣·소품·감각 묘사로 암시한다.
- 폭력·자해는 상처·출혈·투신 순간을 그리지 않는다.
- 저작권: 노래 가사·기존 작품 문장·캐릭터를 옮기지 않는다. 특정 작가 이름이나 작품명으로 화풍을 지시하지 않고 특징을 말로 쓴다.
- 확인되지 않은 사실을 사실처럼 쓰지 않는다.
